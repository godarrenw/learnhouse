## 部署中查出并修掉的脚本 bug

`deploy.sh` 里所有 docker 调用漏掉了 sudo。

生产 NAS 上 `SAM-IPA518` 没有 docker.sock 权限，docker 命令必须走 sudo。
但 `check_containers` / 取镜像层 / 镜像存在性检查 / 补丁校验这四处用的是不带 sudo 的
`remote`，全部失败；而调用处大多写着 `|| echo missing` 或 `|| true`，失败被悄悄吞掉。

表现是预检报「五个容器全部 missing」，而它们其实都好好跑着 —— 同一时刻
`backup.sh` 里的 `docker exec` 是成功的，因为那条走的是 `remote_sudo`。

**中止发生在任何写操作之前，生产没被碰到。** 预检这道闸拦住了，虽然是因为错误的理由。

修法是新增 `dk()` 作为跑 docker 的统一入口，内部走 `remote_sudo`，六处调用全部改用它。
修完先在生产上单独验证了 `dk` 能拿到真实状态，才重跑部署。

**为什么演练四轮没暴露它**：本机演练模式下 `remote_sudo` 就是 `bash -c`，
不需要提权，两条路径行为相同。这类「只在有权限边界的那一侧才会犯的错」，
本机演练结构上验不出来 —— `REHEARSAL.md` 里「SSH 那条路完全没走」那条未验项，
说的就是这个。

## 回滚方法

```sh
# compose 换回上一个 tag 后重建，或直接从回滚点恢复配置
docker-compose -p learnhouse-nas -f docker-compose.yml up -d --force-recreate \
  learnhouse-app ssr-fwd nginx
```

回滚到**切换自建镜像之前**的那份 compose 时，它含 6 条 `./patches/...` 挂载，
NAS 上的 `patches/` 目录必须还在 —— 已确认它仍在，且仍被 `backup.sh` 打进 config 归档。
